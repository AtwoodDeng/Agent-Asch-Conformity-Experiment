# 实验运行记录

每次跑测都必须先建目录、先登记，再运行；结束、失败或中断后更新同一份根目录记录。适用于本次用户要求执行的实验，不因本技能额外启动实验或模型调用。

## 路径与归属

- 实验根目录指该研究项目的根目录（例如 Society/Project/Asch-Conformity-Experiment），不是整个工作区，也不是单次运行目录。结合当前任务、规划和运行入口确定。
- 总记录固定为实验根目录的 `实验记录.md`。保留原有内容和历史条目；若已有同用途记录，迁移或整合时不丢失历史。
- 每次独立跑测新建 `results/_local/YYYYMMDD_HHMMSS_简短目的/`，路径相对于实验根目录。名称冲突时追加序号，禁止覆盖已有运行。
- 每次目录下保存 `raw/` 原始数据、`logs/` 运行日志、`config/` 实际配置快照；分析产物可放 `analysis/`。有固定产物结构的运行器可直接以该次目录为输出根目录，保留其内部结构。
- 同一次明确的断点续跑可继续使用原目录，但追加 attempt 编号及时间、参数、断点和结果记录；独立复跑或改变参数的新跑测必须建新目录。

## 运行前必须完成

1. 确定实验根目录，读取现有 `实验记录.md`，创建本次独立目录。
2. 在根目录记录中追加本次 run ID、状态“准备中”、实验目的、跑测内容、准备时间和时区、计划参数、相对数据目录链接。
3. 参数应能重建此次运行：实验阶段与条件、模型名称/版本、引擎与驱动模式、会话/组/agent 数量、题数/轮数、种子、采样参数、历史策略、干扰设置、并发、超时与重试设置，以及适用的配置/提示词/刺激版本或哈希、源码版本和启动命令。区分计划值与实际生效值；不适用的字段可省略，尚未确定的字段注明待定，不编造。
4. 保存本次实际配置快照，显式把运行器输出指向本次目录，并保证日志和原始数据可落盘。运行器不能指定输出目录时，先补齐输出路由再运行，不能依赖结束后从易覆盖的共享目录搬运。
5. 启动时记录实际开始时间、实际生效参数，状态改为“运行中”。时间包含时区，默认使用用户当前时区。

## 运行期间与结束后

- 原始请求/可见输入、模型原始响应、逐题/逐轮事件、评分所需数据、错误和重试记录均保存在本次目录；保留原始内容，不用统计汇总替代，不以再次运行覆盖旧数据。
- 不把 API key、令牌、密码等凭据写入记录、命令快照或日志；只记凭据变量名称或来源。可见输入指实验材料，不含认证信息。
- 长任务按已有批次或检查点更新根记录中的进度；续跑、参数变化、失败均追加有时间的记录。
- 每次结束、失败、中断后更新同一 run 条目：实际结束时间、耗时、最终状态、完成/失败/缺失数量、实际参数与计划的差异、原始数据/日志/报告链接、简短结果和后续动作。失败产物也保留；结束时间未知时明确标为未知，不能假装成功。
- 明确区分离线脚本自检与真实模型实验。只报告实际观察到的结果，未生成的数据标注缺失。
- 原始数据保持原样；重新分析使用单独的分析输出并补充记录。仅分析既有数据无需伪造新实验运行。
- 汇报时提供根目录 `实验记录.md` 和本次数据目录的位置。

## 根目录记录条目模板

文件顶部可以维护简短索引；每次运行追加如下条目，运行后回填实际值并保留变更历史。

```markdown
## run ID — 简短目的

- 状态：准备中 / 运行中 / 完成 / 失败 / 中断
- 实验目的：
- 跑测内容：阶段、条件、覆盖范围；离线自检或真实模型实验
- 时间：准备时间；实际开始；实际结束；时区；耗时
- 数据目录：[本次运行](results/_local/run-id/)
- 计划参数：
- 实际参数及配置快照：
- 代码、提示词与刺激版本：
- 启动命令（无凭据）：
- 完成情况：实际会话/试次/调用数、失败与缺失
- 结果摘要及产物链接：

### 执行与变更记录

- 时间：启动、检查点、续跑、差异、失败原因或结束情况。
```
